# r5-i18n: Arabic and English interface (E26), and the screens of R5

Decision implemented: the interface in Arabic (right to left) and English, chosen by each user and kept with the account.

- `client/i18n/`: `t()` with the English text as key (English unchanged, so the existing browser tests still read it);
  `ar.ts` (about 330 texts, plain Modern Standard Arabic, pharmaceutical terms of the shop floor), `en.ts` for keys made from
  server codes (signature meanings, statuses, step and field types, setting names, units); server errors translated by
  code, else the server's own message; dates in the user's language.
- The page direction follows the language; directional styles became logical (`text-start`, `ms-`, `ps-`, `border-e`,
  `border-s-4`); codes, passwords and user names are typed left to right in both languages.
- The language is kept with the account: `migrations/0330_user_language.sql`, `GET/PUT /api/me/preferences` (audited).
  Before sign-in the browser's language is used, for the page only (nothing is stored on the device). The switch on the
  sign-in page sits after the form, so the keyboard still reaches the user name first (an existing test caught it).
- New screens: Settings (sessions, sign-in, yield, directory with the connection test; reason and signature per change),
  the QA review of a built-in logbook type, the recipe's own yield limits in the designer.

Gate needs: the e2e seed (two accounts with every role, one per viewport, since the language belongs to the account);
route table (69).

Evidence: `tests/unit/i18n.test.ts` 5 (every key the screens use is in Arabic, nothing unused, Arabic values with the same
placeholders, no visible English text bypasses t()), `tests/api/preferences.test.ts` 1, `tests/e2e/i18n.spec.ts` 4 (every
screen in Arabic at tablet and desktop size: right to left, no horizontal scroll, 44 px targets, no interface English; the
choice survives a reload and a new sign-in from an English page); the 34 English browser tests still pass. Screenshots
looked at (settings on a tablet in Arabic); the setting units were then translated too. Planted faults: a missing Arabic
key and an untranslated text: both caught.

NOT verified: the Arabic wording by a native reviewer at the plant (it should be reviewed as part of the validation).
